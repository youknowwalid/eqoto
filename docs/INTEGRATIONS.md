# EQOTO — external integrations and setup

EQOTO is a **paper-trading and education platform**. Nothing in this repository moves real money or places orders with a broker.

## 1. Database (required)
Apply `supabase/migrations/0001…0006` in order to the Supabase project the app points at (`src/lib/config.js`, or `VITE_SUPABASE_URL` / `VITE_SUPABASE_KEY`).
All migrations are idempotent and non-destructive (`create … if not exists`, `create or replace`, `on conflict do nothing`), so they can be run on an existing project; existing rows are never deleted or reset.

```bash
supabase link --project-ref <ref>
supabase db push
```
or paste each file into the Supabase SQL editor in order.

Make the first admin: `update public.profiles set role = 'admin' where email = 'you@example.com';`
`0006_seed_demo_data.sql` inserts **synthetic** instruments, investors, lessons and calendar rows only when the tables are empty. Skip it on a project that already has data.

Verified locally on PostgreSQL 16: migrations apply twice cleanly; RLS blocks self-promotion, balance edits, direct ledger writes and forged posts; concurrent orders and duplicate idempotency keys are serialised correctly.
Not verified here: Supabase-specific behaviour (Auth hooks, Storage API) — see "Release checklist".

## 2. Market data
`src/lib/marketData.js` is the only module that knows where prices come from. Each instrument has `data_source`:

| Value | Meaning |
|---|---|
| `simulated` (default) | Random-walk prices generated by `tick_prices()`. Always shown with a **Simulated price** badge. |
| `licensed` | Prices written by a licensed provider via `public.ingest_quotes(jsonb)`. Shown as **Licensed feed** (or *stale* after 20 min). |

To connect a licensed provider (**not connected in this repository; requires a provider contract and API key**):
1. Obtain a market-data licence that permits display to your users.
2. Create a Supabase Edge Function that holds the provider key as a secret, fetches quotes on a schedule (Supabase Cron) and calls, with the service-role key,
   `select public.ingest_quotes('[{"symbol":"AAPL","price":123.45,"prev_close":122.1,"as_of":"2026-01-01T15:00:00Z"}]')`.
3. Insert the instrument with `data_source = 'licensed'`. `ingest_quotes` rejects non-service-role callers and ignores simulated instruments.
Orders remain paper trades even for licensed prices. Real-money trading would need a regulated broker integration and compliance review, which this project intentionally does not include.

## 3. Payments / deposits / withdrawals
Wallet deposits and withdrawals are **simulated requests** reviewed by an admin (`admin_review_tx`). There is no payment processor. A real processor (and the legal/compliance work it implies) would be a separate integration.

## 4. Email
Not configured. Supabase Auth sends its own confirmation/reset emails; configure SMTP and templates (use the EQOTO name) in the Supabase dashboard → Authentication → Emails.

## 5. Identity verification
Documents are uploaded to the private `kyc` bucket (owner folder + admin read only) and reviewed manually by admins. No automated KYC vendor is integrated.

## Release checklist
- [ ] Run migrations on the production Supabase project (see §1) **before** deploying this frontend (`place_order` gained an idempotency-key argument).
- [ ] Set an admin user.
- [ ] In Supabase Auth settings, review email confirmation, SMTP and the site URL (`https://eqoto.vercel.app`).
- [ ] Confirm the `kyc` bucket is private and its policies exist (`select * from storage.buckets where id = 'kyc'`).
